=== SHUFFLE / DETERMINISM (current behaviour — post 9b70cc9) ===
  A painting's identity is the 4-tuple (song, artist, style-variant). The
  SAME tuple ALWAYS renders the identical painting; the dice only chooses
  WHICH tuple to jump to next, never how a tuple looks.
    · pollockSessionSeed — deterministic hash of the song's chords.
    · paintPhase — the variant index fed INTO drawing. Pure read:
        explicit artist → phaseIndex (Next cycles that artist's styles);
        shuffle         → shufVariant (set by the dice roll).
    · _diceRoll() — on Next/Play with Dice ON: picks a RANDOM next tuple.
        full shuffle → random artist (shuffleArtistIndex += random) + random
        style (shufVariant); manual artist → random style of that artist.
        Range respects tier variant cap (free 2 / pro 6).
    · No Math.random() ever reaches the painted output — re-landing on the
      same tuple repaints identically.
  Concept block 'random' documents this ("same combo, same painting").

=== SOURCE MODES (05-main) ===
  Score   MIDI / MusicXML / audio (mp3/wav/m4a) upload → transcribe → paint.
  Image   ◫ drop a painting → two AI paths:
            - MFI (Mood From Image): composeFromImage() → short piece from the
              image's MOOD. Prompt is mood-DRIVEN (key/tempo/register/dynamics
              derived from the named emotion; no fixed C-major/tempo-90
              default) so different photos yield audibly different music.
              Content-hash cached (_imgMoodCache).
            - AI Compose (Image): aiComposeFromImage() → longer piece that
              also honours colour + colour→tone mapping (mat.palette/energy/
              arc/mood). Content-hash cached (_imgComposeCache).
  Compose ✦ live on-screen piano; chord-name recognition; golden-ratio frame.
  Mic     🎙 sing/listen; dual stores (listenBlobRef); ambient → painting.
  Plus: Morph (blend two moods), Vary (same painting, new key/tonality),
        Atmosphere, Recently Played (Compose + Mic).
